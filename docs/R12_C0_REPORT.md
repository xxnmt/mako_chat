本次在现有 v33 重用 review_failure 和租约。Reflection 的领取版本参与 CAS，现有失败计数的内容指纹不因领取版本增加而重置。新事件仍可作为独立来源排队。同源依赖冲突会按有界退避刷新上下文；实现没有新增依赖变化订阅，当前依赖变化不会立即取消已生效的旧退避。

## 处理矩阵

|结果|内部状态|联系与重领|
|---|---|---|
|合法内部、外发合法|原事务落库|照既有契约等待 Outbox；无重复入队|
|合法内部、外发 malformed / withheld|内部提交|格式非法不写待发送行；核验拒绝可留现有 withheld 审计|
|prior 或证据已变化、内部结构非法|内部回滚，保留具体短码|按现有失败退避刷新，避免同一来源每分钟重领|
|来源消失|内部回滚，记录 source_unavailable|不可领取的来源不再派发|
|版本或 CAS 不符|内部回滚|记录诊断，不改新版本|
|源权限失效或 private_writing 被撤销|内部回滚|关闭入口不领取及检索，重新启用后恢复候选资格|
|SQL 或事务故障|事务回滚，报告 db_error|沿用有界退避；若失败记录也无法持久化，原租约负责恢复|
|用户插话和主动让出|原有 yield 路径|不计认知失败；迟到回调不提交|

具体入口见 [Reflection/Concern 提交](../src/memory/privatereflection.cpp)、[调度和回调](../src/app/privatereview.cpp)、[检索前和回调时权限检查](../src/cognition/llmservice.cpp#L1820)。独立 Concern、OpenWake 与提醒继续使用各自的授权。C1–C4 留在审计阶段。

## 真实核验对照

使用 DeepSeek 的 deepseek-v4-flash，在简化 JSON 诊断接口上发送六种合成样本，每种配置和样本只请求一次。两组均为 HTTP 200 六条、结构完整六条、允许两条及拒绝四条。该对照没有写入行动或调用渠道。历史的真实 1024 reasoning 全耗尽有日志佐证，本次小样未再次命中该截断，不能据此给出稳健成功率。

|样本|预期|1024 completion / reasoning / ms|2048 completion / reasoning / ms|
|---|---|---|---|
|主观动机|允许|100 / 74 / 828|128 / 104 / 922|
|有依据事实|允许|1014 / 984 / 5406|136 / 108 / 1313|
|依据不足|拒绝|130 / 91 / 1062|115 / 74 / 1110|
|矛盾|拒绝|97 / 58 / 1312|115 / 87 / 1218|
|遗漏事实|拒绝|392 / 341 / 3047|255 / 208 / 1765|
|越权依据|拒绝|174 / 141 / 1094|162 / 123 / 1156|

选用 2048 作为单次请求上限，保留 failure-closed 和零 repair。它提供额外余量，未有依据宣称消除全部截断或降低延迟。正常生产协议的隔离真实回放验证了 OpenWake 合法联系一次并写一次 mock 回执（completion 345、reasoning 277、1900ms），以及无据声明被 verifier_insufficient 拒绝（267、202、2380ms）。结构完整并不等于批准。截断及错误 JSON 的拒绝路径采用确定性 mock 覆盖。
