# R12-C1 实施与验收

## C0 收尾

Concern 原提交失败经 bool 被折叠为 invalid_or_stale_proposal。非计数分支调用 deferConcernReview，将待审行置为 deferred 且立即到期，而定时 Concern 的领取要求 consider。这可能让到期关注退出原调度，也会在来源符合普通 Reflection 条件时被错误接走。现在 Concern 复用 ReflectionCommitResult。内部校验或数据库失败走持久退避，并恢复到 Concern 的 consider 和 next_check_at。过期版本及 CAS 冲突不写入新一轮。只涉及联系格式时，内部回顾仍可提交，不创建待发送动作。SQL 或事务失败不会写成功状态。已修正 verifier 上限注释。

确定性用例 malformedReviewCommit_defersUntilEligible 从 PrivateReview::receive 实际提交无效内部结构，对 Reflection 和 Concern 分别检查失败短码、有界退避、退避后重新领取及旧回调隔离，Concern 的第二次结果同时验证外发格式错误仍能收尾。

统一了 OpenWake 几项默认及整数范围，并将有效日上限复用到 UI。配置页继续做差异保存、保留未知键及原子写入。服务的真实可用性与配置许可区分，当前 UI 只证明配置上限及覆盖来源，不实时探测 provider 连通性。

[逐项配置生命周期](R12_C_CONFIG_INVENTORY.md) 是源码审计表。字段归属、默认和运行入口为静态复核，有限的 UI 回归覆盖典型场景，逐项实机热更新仍有覆盖边界。群保留、语音模型目录等无效运行项仍保留兼容解析接口。排期 schedule 已删除无效解析但保存保留未知键。
