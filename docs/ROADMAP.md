## 开发顺序

总体目标是茉子拥有连续的生活、共同经历、自己的兴趣和可成长的人格。下面六项任务记录认知核心的工程工作。勾选表示已接入并有受控验证，真实对话验收另记。

2026-11-11 校准后的近期顺序为先交付跨渠道内部认识与表达衔接，再接通一个可持续的实际活动。任务 4、5、6 按这两个可验收阶段协同推进。记忆与审计的后续完善随实际失效场景处理。

## 愿景与现状的对应

校准依据为用户提供的《茉子的存在与生活愿景》0.1。当前认识、输入留存与失败恢复已形成基础，群聊已能在本人主动询问时接续有依据的普通近况，实际使用的稳定性仍需观察。兴趣回顾与文字草稿是已有起点，持续活动协调、跨重启活动恢复、经历驱动的人格成长和内在情绪仍待开发。现有关系数值、立绘标签和换装属于已实现的交互表现。

每个阶段同时记录用户可体验的变化、实际执行结果和已知缺口。一个检索或审计阶段通过后，整体生活连续性的验收继续保留。

## 阶段 A：跨渠道认识与表达衔接

工程进度（2026-11-12）：A1–A4 已接入；A5 分别记录自动化、真实接口样本和实际渠道体验。

实际双群复验中，两轮均引用同一版本人自述。一轮多说作息背景，另一轮把指代不确定说成遗忘。修复后，群聊表达使用已核验版本的引文片段，接收指代判断和表达动作。审计保留引文位置、选中版本、核对时的最新版本及协议错误。下一次实际复验关注公开内容的范围和澄清是否准确。

| 项目 | 已接入的路径 | 验证边界 |
|---|---|---|
| A1 内部认识 | 按已解析主体读取获准留存的事项；相关项给状态、来源原话、报告时间和版本，其余先给目录 | 词项排序有预算；模糊指代可能漏选 |
| A2 运行协调 | CognitiveCoordinator 关联输入、前台队列、观察触发、安静、中断与渠道交接 | 观察异步提交；不会为了回复等待整条后台队列 |
| A3 群聊表达 | 私下判断可按事项补查；本人主动问及普通自述时，公开生成可取得有编号的认识和确定性 | 不开放跨群原文检索；语义保密判断仍需真实样本 |
| A4 证据与时间 | 内部补查、工具、事项核对共享次数预算；校验具体表达引用，记录时间意图与解析结果 | 引用合法不能证明句意；过去自述也不能证明当前状态 |
| A5 验收 | Windows Debug 与 15 个自动测试套件通过；真实接口结果见开发历史 | 自然 QQ/Pet 使用及平台送达需单独观察 |

验收覆盖同一事项在 Pet、主人私聊和群聊中的接续、更正、取消与未定状态。本人主动问及、第三方问及和带保密要求的同类事项分别验证。记录模型实际取得的认识、表达依据及渠道结果，观察有限表达时是否仍能保有连续理解。鲜奶仅作为已有失败样本之一，场景族同时变化人物、事项、时间和措辞。

- [ ] B1 统一事件与注意力。将消息、到期唤醒、活动结果和恢复事件接入协调器。保存当前活动及切换原因，允许延后处理消息、暂停活动或改变安排。若支持先决定是否阅读，决策请求只提供发送者、渠道、时间等元数据，阅读后再开放正文。
- [ ] B2 持久化念头与活动。保存兴趣、目标、来源、进度、暂停原因、下一步意图、版本及真实产物。念头可以保留、重新考虑、行动、延后或放弃。重启后恢复可验证状态，取消与来源删除阻止迟到提交及分享。
- [ ] B3 自主回顾与新目标。在预算内提供稀疏思考机会，结合近期经历和已有关注，允许继续旧目标、形成新念头或休息。无待处理事项、无新事件且未到唤醒条件时直接退出。调用预算与最短间隔可配置，具体数值经实验确定。
- [ ] B4 主动交流与执行反馈。允许基于经历、关注和活动中的念头决定是否主动私聊，选择对象、渠道、内容及时机。执行端校验能力与听众条件，保存交接、失败、未知及平台确认结果，恢复和重试避免重复发送。以后被问起时依据实际结果接续。
- [ ] B5 连续运行验收。覆盖多次唤醒、用户打断、重启、失败、取消与放弃，核对资料、决定、持久状态、真实作品和投递结果。

验收情境可以是昨日讨论故事结局，今天没有新消息时获得一次回顾机会。模型可以形成新构思、完善作品、主动联系、延后或放弃。验收记录依据、简短决策说明、保存结果及实际行动，允许无新目标或无消息发出。另需验证用户建议如何影响活动，活动取消后迟到结果如何处理，以及重启后如何续接。

## 目标与架构决策

同一个茉子应跨渠道维持对人、事项、自己关注和行动结果的连续理解。采用事件驱动的有状态循环：接收事件、读取当前认识、按需回查证据、提出修订、验证提交、判断表达或行动、接收结果。处理可以停在保存疑问、等待信息、沉默或直接回应；每轮不强制经过全部模型步骤。

复用 Qt、SQLite、现有身份归一、渠道与 TTS。认知状态由独立协调层管理，LLMService 逐步收敛到模型通信与协议解析。当前三个私下决定不足以承载完整认知，需要演进，但权限、听众和投递校验仍由服务端构建。内部检索范围、向听众披露的依据和外部动作能力分别形成明确契约。

开发遵循下列顺序。每项完成后记录实现、自动测试、本机构建与真实回放四种证据，不以套件通过替代体验验收。既有回顾和分享路径在迁移期间应只有一个调度归属，避免双重执行。

## 任务 1：建立可回放的诊断基线

- [x] 定义脱敏事件夹具和模型请求/工具响应的回放接口，使用临时库，与真实账号及正式库隔离。
- [x] 按 runId 记录候选来源 ID、检索条件、状态版本、继续或退出原因、工具错误和延迟；默认不记录正文。
- [x] 将当天的跨渠道、更正及结束话题问题转成场景族，加入不同人、不同事情、时间顺序与措辞变化。
- [x] [脱敏场景](../tests/fixtures/cognitive_replay.json) 保留旧版失败表现、可验证的阶段与原日志行号。通过来源、候选、请求与输出定位证据流向；原记录不足以确定的原因标为未知。语义误判与表达偏离需要人工判断。

验收：同一场景可确定重放到相同数据和路由状态，能定位证据在哪一步丢失。模型自然表达由单独评估记录，不断言固定台词。先保留重构前基线，供后续比较。

## 任务 2：定义事项、证据和认识的契约

依赖任务 1。

- [x] 为每个具体事项建立稳定 ID，主体身份、事项归属与听众独立表示。同主题可以有多个事项。
- [x] 定义来源引用、消息时间、事情发生时间、认识更新时间和时间表达锚点。摘要整理时间不得冒充事情发生时间。
- [x] 认识至少能表达已确认、暂定、存在分歧、待确认、取消、结束。新证据可补充、降低确定性、修订或恢复旧认识。
- [x] 保存认识的版本与支持证据；本人自述、转述和模型推断保留不同来源属性。
- [x] 制定独立版本迁移，明确 v10 数据如何作为历史证据接入。旧 topic 名称不自动成为可靠的全局事项 ID。

验收：暂定改期后能同时回答原计划与当前不确定性；另一人的同主题消息不覆盖本人的计划；后来的“还是照旧”能恢复旧安排；迁移失败回滚且重启不重复导入。

## 任务 4：接入可退出的认知循环

依赖任务 3。

2026-11-11 已实现本轮可引用资料的登记、目录与完整认识的区分、私聊近期群消息选择以及主动安静协议。认识提案的版本冲突可定位到变更序号、事项、预期与实际版本。下一轮实机验收关注跨日更正、目录引用的证明范围和自然收尾。统一事件协调、在途输入的语义关联和持续关注仍待实施。

- [ ] 新增统一协调入口，前台消息、回顾与行动结果作为不同类型的事件接入。
- [ ] 先读取相关事项和当前认识，确有信息缺口时自主选择证据源、细化问题或继续检索。
- [ ] 工具 complete 表示调用完成，另行判断证据是否足以回答；failed/partial/empty 不得直接转述为全局不知道。
- [ ] 允许直接回应、提出澄清、等待、沉默。设置步骤、耗时和调用预算；无新证据时停止重复查询。
- [ ] 保留请求隔离，定义用户输入对后台回顾的让步机制与提交版本检查。

验收：普通寒暄可直接结束；缺证据时能够换条件回查；同样的空结果不会无限重试；达到预算时正确表达不确定性；不同会话和后台事件不串线。

本阶段已接入认识更新的有界补查与 v12 证据依赖。隔离库真实模型实验中，主人私聊正确识别了 Pet 里仍暂定的安排。另一次实验中，模型针对未指明的备选时间主动请求前文，读取依据后提交了正确的预约修订。两次观察尚不足以估计成功率。模拟回放覆盖补查、投影与删除后重算。现有自动回放仍不能保证语义关联正确。v13 前台支持直接回应或先选择相关事项再表达，按接收顺序处理输入，单独记录渠道交接、主动安静及技术中断。已选事项的可见依据变化时可以中断在途生成并刷新一次。

下一步以 Pet、主人私聊和群聊的自然对话评估模型何时选择核对、能否接续更正，以及等待时收到的新消息如何影响行动。记录选择的依据、后台提交时点、渠道交接和实际表现。统一活动调度、未整理消息与当前事项的语义关联、进程退出后的任务恢复及渠道回执仍待实施。
